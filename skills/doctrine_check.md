# Skill: The Doctrine Check

- **Action Keyword:** doctrine_check
- **Description:** Whether the foundational and functional docs still describe what the system actually performs — LAW 6, made mechanical. Reports the law chain and any law drafted but not sealed, whether the skill library agrees with the handlers behind it, whether every file holding the version says the same number, any suite tally standing in a living doc (his sitting-79 ruling), and any backticked path in a living doc that resolves to nothing. Each finding names its file and line. Use for "check the doctrine", "do the docs match the system", "is there a discrepancy in the docs", "run the doc sweep".
- **Parameters Needed:** None
- **Says:** check the doctrine, run the doctrine check, do the docs match the system, is there a discrepancy, are the docs out of date, run the doc sweep, check the foundational docs, does the record still hold

Every finding is a comparison between two things on disk. Nothing here is
reasoned about. `deep_research` would seat a model and ask it to reason over
the corpus; asked to find discrepancies it cannot verify, a model invents them,
which is the exact family this estate closed on 2026-09-10.

Dated ledgers are skipped on purpose. A tally in HANDOFF.md or SEAT_LOG.md is a
true record of the day it was written, not a claim about now — flagging it would
be flagging the estate for remembering.
